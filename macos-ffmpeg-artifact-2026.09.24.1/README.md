# Mac app: FFmpeg artifact 2026.09.24.1

Release tag: `macos-ffmpeg-artifact-2026.09.24.1`

This folder and its release are the corresponding source for the FFmpeg,
libbluray, libudfread and dav1d code inside Nsurator for Mac's player.

## Which app builds use it

Nsurator for Mac 5.9.17 (build 8), as built from the app's source on or after
2026-09-24 (the commit that pinned this artifact) up to at least 2026-10-09.
Mac builds made before 2026-09-24 used older artifacts and are not covered by
this release.

The libraries are linked **statically** into two executables in the app:

- `Nsurator.app/Contents/MacOS/NsuratorNative`
- `Nsurator.app/Contents/XPCServices/NsuratorDecoderProbeHelper.xpc/Contents/MacOS/NsuratorDecoderProbeHelper`

The libraries come from a prebuilt artifact,
`nsurator-player-core-ffmpeg-macosx-arm64-2026.09.24.1.tar.gz`
(SHA-256 `4c0ab483555982bc0da9051e1003db6b223f8a01eb0f240cea50ecebd7cebead`),
which holds the static libraries and headers built from the sources here. The
app links `libavformat`, `libavcodec`, `libavutil`, `libavfilter`,
`libswresample`, `libswscale`, `libbluray` (which contains libudfread) and
`libdav1d`.

  macOS 14.0.

  `-Dbdj_jar=disabled -Dfreetype=disabled -Dfontconfig=disabled -Dlibxml2=disabled -Dembed_udfread=true --force-fallback-for=libudfread`.

## Rebuilding the libraries

You need a Mac with Xcode (the artifact used the MacOSX 27.0 SDK), meson,
ninja and pkg-config.

1. Unpack `macos-ffmpeg-artifact-2026.09.24.1-patched-sources.tar.xz`. It holds
   `sources/ffmpeg-8.1.2`, `sources/libbluray-1.4.1` (with libudfread already
   in `contrib/libudfread`), `sources/libudfread-1.2.0` and
   `sources/dav1d-1.5.3`, with our patches applied. Or unpack the upstream
   archives yourself and follow `build/nsurator-macos-native/script/build_nsurator_player_core_ffmpeg_artifact.sh`,
   which copies libudfread into libbluray and lets the core script apply the
   patches.
2. Run the core build script three times, with the same settings the artifact
   build used:

```sh
core=build/nsurator-player-core/scripts/build-ffmpeg-apple.sh
work=/absolute/path/without/spaces
export NSURATOR_PLAYER_CORE_APPLE_BUILD_SLICES=macosx-arm64
export NSURATOR_PLAYER_CORE_FFMPEG_LINK_PROFILE=base
export NSURATOR_PLAYER_CORE_FFMPEG_SWIFTPM_LINK_MODE=static
export NSURATOR_PLAYER_CORE_EXTRA_FFMPEG_CONFIGURE_FLAGS="--enable-libdav1d --disable-network"
export NSURATOR_PLAYER_CORE_EXTRA_RUNTIME_LIBRARIES=libdav1d
export NSURATOR_PLAYER_CORE_DEP_PREFIX="$work/dependencies"
export NSURATOR_PLAYER_CORE_DAV1D_BUILD_DIR="$work/dav1d-build"
export NSURATOR_PLAYER_CORE_LIBBLURAY_BUILD_DIR="$work/libbluray-build"
export NSURATOR_PLAYER_CORE_FFMPEG_BUILD_DIR="$work/ffmpeg-build"
export NSURATOR_PLAYER_CORE_FFMPEG_INSTALL_DIR="$work/ffmpeg-install"
DAV1D_SOURCE_DIR=$PWD/sources/dav1d-1.5.3 "$core" --build-dav1d
LIBBLURAY_SOURCE_DIR=$PWD/sources/libbluray-1.4.1 "$core" --build-libbluray
FFMPEG_SOURCE_DIR=$PWD/sources/ffmpeg-8.1.2 "$core"
```

The source, build and install paths must not contain spaces. The static
libraries end up in `$work/ffmpeg-install/macosx-arm64/lib` and
`$work/dependencies/macosx-arm64/lib`. The scripts skip patches that are
already applied. Keep `NSURATOR_PLAYER_CORE_FFMPEG_LINK_PROFILE=base`: the
scripts' default profile (`full`) adds DVD libraries that FFmpeg treats as
GPL, and that profile was not used for the app.

The artifact build script also runs a step that records the player's runtime
capabilities with our player code. That step only writes a description into
the manifest; it does not change the libraries, and it is not needed to
rebuild them.

## Replacing the libraries in the app

The Mac app links these libraries statically. To use modified libraries, the
two executables listed above must be linked again with them, which needs the
app's own object files. **This repository does not contain them.** The
Nsurator support page (https://www.nsurator.com/support.html#oss) explains how
to ask for the materials needed to relink.

After relinking, the executables and the app have to be signed again. A
re-signed copy no longer carries the Mac App Store signature, so features
that depend on it (in-app purchases, and data containers and app groups tied
to the developer's team) may not work in that copy.

  own player code differs.
